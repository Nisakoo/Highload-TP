# Рассчетно-пояснительная записка для Курсовой работы по предмету "Разработка высоконагруженных приложений"

### 1. Тема и целевая аудитория

**Тип:** ИИ-сервис (аналог Алиса AI)

**Целевая аудитория:** 4,5 млн DAU; 19,0 млн WAU; 30,0 млн MAU (согласно финансовому отчету Q4 2025, но в Q2 2026 WAU 33,2 млн). Продукт ориентирован на российский рынок

**Основной функционал MVP:**
1. Регистрация/авторизация пользователя
2. Диалоги с ИИ*
3. История диалогов с поиском
4. Голосовой ввод, голосовые ответы
5. Загрузка файлов
6. Интеграция с поиском Яндекса

**Ключевые продуктовые решения:**
1. Ответ передается пользователю потоково
2. Для длинных диалогов используется только релевантная часть контекста
3. Пользователь сам решает добавлять поисковые результаты в контекст или нет

### 2. Расчет нагрузки

**Продуктовые метрики:**

| Метрика                  | Значение             |
|--------------------------|----------------------|
| DAU                      | 4,5 млн              |
| MAU                      | 30,0 млн             |
| Средний размер хранилища | 0,006 ГБ/польз./день |

| Функционал MVP / тип действия | Среднее количество действий на пользователя в день |
|---|---:|
| Регистрация пользователя | ~0,003 |
| Авторизация / создание сессии | 1,0 |
| Запрос к ИИ | 4,07 |
| Голосовой ввод | 0,41 |
| Загрузка файла | 0,41 |
| Запрос с использованием поиска | 0,41 |

В начале 2026 года (Q1 2026) Яндекс отчитался, что в день поступает 500-600 тыс. запросов о подборе товара [3], спустя два месяца опубликовали исследование о том, как пользователи используют Чат с Алисой [4] - согласно ему запросы о товарах составляют около 3% (тут стоит сделать оговорку, что за два месяца все могло поменяться, продукт растет, учитывая, что за два квартала WAU увеличился практически в два раза, но будем считать, что за два месяца мало что поменялось) - отсюда следует, что примерно ежедневно в Чат с Алисой приходит 16,6-20,0 млн запросов - предлагаю взять среднее 18,3 млн запросов в день. Предлагаю считать, что на конец Q4 2025 и на начало Q1 2026 ключевые продуктовые метрики не изменились, тогда в день на одного пользователя приходится 18,3 / 4,5 = 4,07 запроса - то есть один пользователь в среднем делает 4 запроса

Опытным путем (бесконечным ctrl+c ctrl+v) определил, что максимальный размер поля ввода 100'000 символов. Также опытным путям (попросил Алису рассказать длинную историю и посчитал символы) выяснил, что максимальный размер вывода (6494+5713+5917)/3 = 6041 символа - будем считать, что максимальный ответ 6500 символов. Таким образом, на один запрос-ответ приходится 106'500 символов, текст хранится в UTF-8, один символ кириллицы занимает 2 байта, тогда получается 213'000 байт, это 0,203 МБ на один запрос, то есть в день 3,5 ТБ в день

Согласно документации к одному сообщению можно прикрепить только один файл размером не больше 100 МБ (про ограничение на диалог не сказано), но будем считать, что в среднем файл весит 10 МБ и примерно 10% запросов приходят с файлами - в день будет 1,83 млн файлов, то есть 18,3 млн МБ, то есть 18,3 ТБ в день

Голосовой ввод: голосовой запрос можно не хранить, досточно перевести его в текст, поэтому будем считать его также как и текстовый запрос. Голосовой вывод: будем считать, что сначала модель генерирует текстовый ответ, а потом он прогоняется через SpeechKit, то есть получается тот же текстовый запрос + место на хранение аудио. Посчитаем сколько займет аудио, в среднем синтез речи выдает 900 символов/минута, то есть 6500/900 = 7,22 минуты. Пусть аудио хранится в Opus 32 kbps, получается 4000 байт на секунду, то есть 7,22 * 4000 * 60 = 1,73 МБ на запрос, будем считать, что примерно 10% запросов голосовые, тогда в день получается 1,83 млн * 1,73 МБ = 3,0 ТБ в день

Наконец, поисковые ответы: будем считать, что поисковые ответы прокидываются в модельку при этом это не влияет на лимит 100'000, то есть контекст модельки позволяет прокинуть поисковые результаты. Также не будем хранить результаты, а только прокидывать их в один запрос (пусть кэшированием занимается поисковый движок), единственное, что надо будет сохранить - это ссылка на источник, но, думаю, это ничтожно малый объем

Таким образом, в день получается 24,8 ТБ в день, то есть 0,006 ГБ в день; в месяц (30 дней) 744 ТБ, тогда в среднем на одного пользователя в месяц приходится 0,025 ГБ
